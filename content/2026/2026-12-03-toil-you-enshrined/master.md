Five things I have automated that I should have deleted instead.

The report nobody read. It was generated weekly for years, by hand, until somebody automated it. The automation ran for three more years. When it finally broke, we waited to see who complained. Nobody did.

The approval step that only ever said yes. A ticket routed to a queue for sign-off, approved every time without question because the approver had no basis to refuse. Automating it made the rubber stamp faster. Removing it would have meant admitting the control was theatre, which is a harder conversation than writing a script.

The reconciliation between two systems that disagreed. Both were authoritative for the same data, so they drifted, so we automated a nightly correction. The script worked beautifully for years and guaranteed nobody ever fixed the actual problem, because the symptom had stopped being visible.

The cleanup for a process that should not have made the mess. A job left temporary files behind, so a second job removed them. Nobody went back to the first job, because the second one was cheap and reliable and the mess was gone.

The manual check after a change, automated into a test that checked the wrong thing — because it was automating what we did, not what we meant. That one ran green for a long time.

The pattern is the same every time. Automation lowers the cost of a task to near zero, and nothing that costs zero ever gets reviewed again. The work becomes invisible rather than absent, and invisible work is permanent.

So the question before automating is not "can this be automated." It is "should this still happen at all." And that question gets harder to ask afterwards, because the script becomes evidence that somebody thought it was worth doing.

Automation is a commitment. Deleting is cheaper, and you only get one easy chance to do it.

What have you automated that should have been deleted?
