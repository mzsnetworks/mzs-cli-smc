## Thread (alternate)

1/ Nobody needs an orchestrator on day one. You earn one.

2/ The pitch: buy the platform, get maturity. But orchestration doesn't create capability — it multiplies what you already have.

3/ Multiply reliable tasks → leverage. Multiply flaky ones → an expensive way to run broken scripts in the correct order.

4/ What earns it: tasks that are idempotent. If running a script twice makes anyone nervous, it isn't ready to run unattended at 2am.

5/ Data you trust. A stale source of truth doesn't slow the tool down — it executes confidently against the wrong list.

6/ A rollback somebody has actually run. Half-applied is the normal failure mode of orchestrated change.

7/ Failure you can see. "The job failed" isn't observability.

8/ An orchestrator doesn't make your automation mature. It reveals how mature it already was. #NetworkAutomation
