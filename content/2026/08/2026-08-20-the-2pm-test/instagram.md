# Instagram — the-2pm-test

What percentage of your changes would you be willing to run at 2pm? 🕑

Not "could" — willing. Users online, phones ringing, finance three desks away.

For most teams the honest answer is low. And a 2am window isn't a safety control. It's a confession.

What the window actually buys:
→ not safety — same commands, same devices, same blast radius
→ fewer witnesses

We schedule at 2am because we expect breakage and we'd rather nobody watch. That's not managing risk. It's managing embarrassment. 🌙

And it costs more than people admit:
→ your worst engineers — not least skilled, least rested
→ slower detection, because normal traffic is gone
→ rollback calls made by someone awake nineteen hours
→ vendor TAC running its B-team

You traded observability, judgment and support for privacy.

Some changes do need a quiet network — a core upgrade, a migration that drops sessions no matter what. Fine. But that's the exception you can name, not the default you stopped questioning.

The test is diagnostic: sort last quarter's changes by which you'd run at 2pm. The failures aren't about the hour. They're thin pre-checks, theoretical rollback, unclear blast radius, or a change that's simply too big. 🔧

Fix those four and it moves into daylight on its own. Nobody has to be brave.

The goal isn't to be braver at 2am. It's to build changes you'd run at 2pm.

What percentage of yours would pass? 👇
