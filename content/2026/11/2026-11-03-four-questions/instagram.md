# Instagram — four-questions


Four questions before I automate anything. 🤔

None of them is "can this be automated."

→ How often does it actually run?

Not how often it feels like it runs. I've built things for a "weekly" process that happened twice a year. I've skipped things that happen four times a day because nobody mentioned them.

The honest number decides whether it's worth doing at all.

→ Who else runs it?

If the answer is only me, I'm not automating a process — I'm building a personal tool and calling it automation. ⚠️

That's fine if everybody knows. But something a colleague runs at 2am needs error messages written for them, not for me.

→ What happens if it half-finishes?

This is the one that gets skipped, and it's the one that hurts.

A script that stops two devices into a five-device change leaves the network in a state nobody designed. Either it's safe to rerun from the start, or it tells me exactly where it stopped. ⚙️

→ How will I know it did what I think it did?

Exit code zero means the script finished. It doesn't mean the change is in place and working.

If I can't name the check that proves the outcome, I automated the typing — not the task.

None of these are technical. They're about the context the script runs in, and that's what makes automation safe or dangerous.
