# Instagram — what-survives-you


Did your last outage change a document, or change a default? 📄

Only one of those is still working in two years.

Both feel like closure on the day. The postmortem gets written, somebody updates the runbook, the item is closed.

Then the people who were on that call move on. ⚠️

One changes teams. One leaves. One is still there but has run forty incidents since.

The document is exactly where it was. Nobody opens it — because opening it requires already suspecting the thing it warns about.

That's the whole difference:

→ A document transmits a lesson only to someone who goes looking
→ A default enforces it on someone who never heard the story

The defaults are small and specific. A field in the change template so the question gets asked every time. A validation step that fails on the condition that caused it. ⚙️

None of them require anyone to remember anything. That's the point.

So I ask a blunt question now: if everybody in this room left tomorrow, what would still stop this happening again?

If the answer is a document, we recorded the incident rather than fixed it.

Write the document too — it carries the reasoning, and the reasoning is what lets a future engineer change the default safely instead of deleting it.

But the test is survival.

What did your last postmortem actually change?
