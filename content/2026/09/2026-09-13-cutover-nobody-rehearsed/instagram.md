# Instagram — cutover-nobody-rehearsed

Every project we've been called into late failed at the same milestone. ⚠️

Not design. Design gets reviewed by four people who all want to be right.

Not procurement. Not staging either — the gear arrives, gets built, labeled, configured, and works on the bench.

It fails at the cutover.

Because the cutover is the first time any of it runs together. ⚙️

Everything before it was tested in pieces.

The cutover is the only integration test the project ever gets — and it runs in production, once, at 2am, with users arriving in six hours.

So the question we ask before a date gets committed: has anyone actually run this?

Reading the runbook aloud in a conference room is not a rehearsal.

A rehearsal has the actual commands, executed by the person who will execute them, in the actual order, against something real — with a clock running.

What a rehearsal reliably surfaces:

→ the step budgeted at ten minutes that takes forty
→ order dependencies nobody wrote down
→ a credential on one laptop, owned by someone on PTO that weekend
→ the back-out that has only ever been written

That last one matters most.

A rollback you've never performed isn't a safety net. It's a second unrehearsed cutover, attempted by tired people at 4am when the first one has already gone wrong.

Design gets reviewed. Hardware gets staged. The sequence gets discovered — at 2am, in front of everyone.

When did you last rehearse a back-out? Not write one. Run one. 👇
